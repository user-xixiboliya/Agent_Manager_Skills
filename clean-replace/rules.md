# 具体规则：禁止清单、命名、测试、文件增长

> clean-replace 的参考文件。阶段 D、E 开始前读；写代码、删代码、改测试时对照执行。

## 禁止清单

### 文件层面

| 禁止做法 | 示例 | 正确做法 |
|---|---|---|
| 版本化文件名 | `model_v2.py`、`train_new.py`、`loss_improved.py` | 直接修改 `model.py`；如果文件名描述的是旧方法，改成描述新方法的名称 |
| 备份文件 | `model_bak.py`、`model.py.orig`、`model_copy.py`、`model (1).py` | 直接修改原文件，依赖 Git 保存历史 |
| 代码归档目录 | `archive/`、`old/`、`legacy/`、`deprecated/`、`backup/` | 删除旧代码文件 |
| 平行目录 | `models/` 和 `models_new/` 并存 | 只保留 `models/`，在原目录中替换 |
| 临时代码残留 | `test_tmp.py`、`debug.py`、`scratch.ipynb` | 用完就删除 |
| 未经要求的总结文档 | `CHANGES.md`、`MIGRATION.md`、`SUMMARY.md` | 修改历史写进已有的 CHANGELOG、实验记录和修改索引，修改说明写进最终报告 |

### 代码层面

| 禁止做法 | 示例 | 正确做法 |
|---|---|---|
| 注释掉旧代码 | `# old_encoder = ResNetEncoder()` | 直接删除 |
| 兼容别名 | `ResNetEncoder = ViTEncoder` | 修改所有调用方，删除旧名称 |
| 转发函数 | `def old_fn(x): return new_fn(x)` | 修改所有调用方，删除 `old_fn` |
| 新旧切换开关 | `if cfg.use_legacy: ... else: ...` | 只保留新路径，删除开关 |
| 弃用标记 | `@deprecated`、`warnings.warn("will be removed")` | 现在就删除旧实现 |
| 过渡注释 | `# TODO: remove old impl`、`# 旧逻辑暂时保留` | 不写这类注释，直接完成删除 |
| 死分支 | `if False:`、`if method == "old":` | 删除整个分支 |
| 重复实现 | 已有 `normalize()`，又新增 `normalize_input()` | 复用或修改已有函数 |

### 配置层面

| 禁止做法 | 示例 | 正确做法 |
|---|---|---|
| 新旧配置键并存 | 同时存在 `encoder_type` 和 `encoder_name` | 只保留一个，修改所有读取位置 |
| 保留旧方案的配置文件 | `configs/resnet.yaml` 仍在，但已没有代码使用 | 删除，或改写成新方案 |
| 保留旧方案的参数 | 已替换优化器，但 `momentum` 参数还在 | 删除只属于旧方案的参数 |
| 旧默认值 | 默认值仍指向旧方法 | 改成必填项，或者让默认值指向新方法；改成哪种需要先问用户 |

### 文档层面

| 禁止做法 | 示例 | 正确做法 |
|---|---|---|
| 当前文档中新旧描述并存 | README 写“我们使用 ResNet（现已改为 ViT）” | README 只写“我们使用 ViT”；替换记录写进 CHANGELOG |
| 在方法文档中写迁移历史 | docs 写“v1 使用 A，v2 改用 B” | 删除历史描述，写进 CHANGELOG 和实验记录 |
| 过时示例 | README 中的命令仍使用旧参数 | 改成能运行的新命令 |
| 过时 docstring | 函数已改，docstring 仍描述旧行为 | 同步改写 |
| 改写历史文档 | 把 CHANGELOG、实验记录或修改记录中的旧方法名替换掉 | 历史条目保持原样，只追加新条目 |
| 擅自修改用户的规则文件 | 直接改写 AGENTS.md、CLAUDE.md 中的描述 | 列入清单，用户确认后再改，见 change-index.md 中“与 AGENTS.md、CLAUDE.md 的关系” |

### 实验产物层面

| 禁止做法 | 示例 | 正确做法 |
|---|---|---|
| 删除实验产物 | 删除旧方法的结果、日志、权重 | 不删除，列入报告交给用户 |
| 移动或重命名已有产物 | 把 `runs/resnet/` 改名为 `runs/resnet_old/` | 保持原样；需要整理时先问用户 |
| 产物散落 | 日志在根目录，权重在 `ckpt/`，指标在 `output/` | 同一次运行的所有产物放在同一个运行目录 |
| 用状态词命名产物目录 | `results_new/`、`runs_old/`、`baseline_v2/` | 按方法名命名，例如 `results/vit_encoder/` |
| 覆盖已有结果 | 新实验写进已有运行目录 | 目标目录已存在时先问用户 |

### fallback 层面

| 禁止做法 | 示例 | 正确做法 |
|---|---|---|
| 异常时退回旧实现 | `try: ViTEncoder() except: ResNetEncoder()` | 删除 except 分支，让错误直接抛出 |
| import 失败时退回 | `try: import timm except ImportError: from .resnet import ...` | 在依赖文件中声明依赖；缺失时直接报错 |
| 默认值指向旧方法 | `cfg.get("encoder", "resnet")` | 改成必填项，或者让默认值指向新方法；改成哪种需要先问用户 |
| 注册表查不到时退回 | `MODELS.get(name, ResNetEncoder)` | `MODELS[name]`，查不到时报错并列出可选项 |
| `or` 兜底 | `build(name) or ResNetEncoder()` | 删除兜底，构建失败时报错 |
| 吞掉异常 | `except Exception: pass`、`except: return 0.0` | 删除，或者只捕获明确的异常并重新抛出 |
| 文件缺失时静默改用别的文件 | 找不到 ViT 权重时，改为加载 ResNet 权重或随机初始化 | 报错，并说明期望的路径 |
| 设备静默降级 | CUDA 不可用时，自动改用 CPU | 报错；或者用户明确要求时，输出警告后再降级 |
| 数据静默替换 | 找不到真实数据时，改用随机数据或合成数据 | 报错 |
| 数值异常时偷偷修正 | loss 为 NaN 时改用旧 loss，或者直接置零 | 报错，或者用户要求时记录日志后终止 |

扫描中发现项目里原本就有 fallback 时，不擅自修改，在确认点 2 中列出，交给用户决定：

| 类型 | 默认建议 |
|---|---|
| 退回旧实现的 fallback | 删除。它会让旧方案继续生效，属于本次替换范围 |
| 与本次替换无关的 fallback | 列出位置和触发条件，询问是否删除 |

每项都写清：

- 位置
- 触发条件
- 触发后实际会走哪条路径

## 命名规范

### 判断旧名称是否可以直接复用

先问一句：**旧名称描述的是“职责”，还是“方法”？**

| 旧名称 | 类型 | 处理方式 |
|---|---|---|
| `Encoder`、`build_model`、`Trainer`、`compute_loss` | 职责名 | 保留名称，让它直接承载新实现 |
| `ResNetEncoder`、`PPOTrainer`、`mse_loss`、`AdamOptimizer` | 方法名 | 改成描述新方法的名称，例如 `ViTEncoder`，并同步所有引用 |

如果判断不了，或者有多个合理的新名称，在确认点 2 中让用户选择。

### 新名称的要求

- 描述“它是什么”，例如 `ViTEncoder`、`TDLambdaCritic`、`ShiftAugment`
- 不用版本号或状态词，例如：
  - `v2`、`v3`
  - `new`、`old`
  - `improved`、`better`、`fixed`、`final`、`latest`、`tmp`
- 与项目现有命名风格保持一致，包括大小写、前后缀和缩写方式
- 文件名、类名、配置值、文档术语、实验产物目录名统一使用同一个名字，不要混用多个叫法

### 改名时需要同步的位置

如果改了名称，以下位置都要同步：

- 定义处
- import 和导出列表，例如 `__init__.py`、`__all__`
- 调用方
- 注册表和工厂函数中的字符串名
- 配置文件中的值
- 命令行参数
- 测试名和测试中的断言
- 当前文档、注释、docstring
- 修改索引中的文件职责表
- 新实验的日志字段、实验名、产物目录名

以下内容不改：

- 已经产生的实验产物
- CHANGELOG、实验记录和修改记录中的历史条目

## 测试的处理规则

测试也必须同步替换。

### 不同测试的处理方式

| 测试类型 | 处理方式 |
|---|---|
| 测试旧方法内部细节，例如 ResNet 的 block 数 | 删除 |
| 测试对外行为，例如输出形状、数值范围 | 保留，并改为针对新实现 |
| 测试旧方法专属参数 | 删除 |
| 新方法有新的关键行为 | 补充测试；补充哪些测试，在确认点 2 中说明 |
| 测试 fallback 行为，例如“构建失败时退回旧实现” | fallback 删除后，改为测试“出错时直接报错” |

### 禁止的测试处理方式

- 为了让测试通过，删除仍然有效的行为测试
- 放宽断言，例如把精确比较改成 `assert x is not None`
- 跳过失败的测试，例如 `@skip`、`pytest.mark.xfail`
- 保留断言旧行为的测试，并标记为预期失败
- 在测试中加 fallback 或吞掉异常，让测试通过

测试失败时，先判断原因：

- 新实现有 bug：修改实现
- 测试仍在验证旧行为：修改测试
- 无法判断：触发确认点 3

## 控制文件增长与防止接口重复

### 什么时候允许新增文件

只有满足以下任一条件时，才新增代码或文档文件：

- 新实现在概念上是独立模块，放进现有文件会明显破坏现有结构
- 项目已有约定要求这样组织，例如每个模型一个文件
- 用户明确要求新建文件

计划新增的文件必须在确认点 2 的清单中列出，并说明原因。

修改索引（`docs/agent-index/` 下的文件）是本规范要求的文件，不受本条限制，但第一次创建时要在确认点 1 中确认。

### 临时代码

- 调试脚本优先放在系统临时目录，例如 `/tmp`。
- 如果只能放在项目目录中，最终报告前必须删除。
- 这里说的是 agent 写的临时代码，不包括实验产物。实验产物按 artifacts.md 处理。

### 新增接口前先查

新增函数、类、配置项或命令行参数前，先查有没有相同职责的内容：

- 先看文件职责表，找职责相近的文件，再阅读这些文件
- 再用职责关键词和同义词搜索，例如 normalize、standardize、encode、embed

```bash
git grep -n -i -E 'def .*(normalize|norm|standardize)'
```

### 判断是否重复

出现以下情况时，可能是重复：

- 两个函数的输入、输出相同，只是名字不同
- 一个函数只是给另一个函数加了默认参数
- 两个配置项控制同一种行为
- 两个类的方法签名大部分相同

### 发现重复后的处理

- **本次新增造成的重复**
  - 合并到已有实现，删除新增的重复内容。

- **项目原本就有的重复**
  - 不擅自合并。
  - 在报告中提出，或在确认点询问用户是否顺带处理。
