# 实验产物管理

> clean-replace 的参考文件。阶段 A 查项目规范时读；要运行实验或发现散落产物时对照执行。

实验结果、日志、权重由用户管理和删除。agent 的责任是让产物放得整齐、找得到、分得清，而不是替用户清理。

## 优先级

如果项目已有关于实验产物的规范，以项目规范为准。项目规范可能写在以下位置：

- AGENTS.md、CLAUDE.md
- README 或 docs 中的说明
- 已有的目录结构
- 训练框架的输出目录配置，例如 Hydra、Lightning、wandb 的配置
- 用户提供的规则文件

本文件中“存放位置”和“目录结构”的规则只在项目没有相关规范时使用。

本文件的规则与项目规范冲突时，按项目规范执行，并在最终报告中说明。

不过，以下几条规则不受项目规范影响，始终有效：

- agent 不删除、不移动、不重命名已有的实验产物
- agent 不覆盖已有的运行目录

## 存放位置

- 先找项目已有的统一产物目录，例如 `results/`、`runs/`、`outputs/`，并沿用它的目录结构。
- 找不到统一目录，或者存在多个候选目录时，询问用户放在哪里。
- 不在项目根目录、源码目录或配置目录中写实验产物。

## 目录结构

同一次运行的所有产物放在同一个运行目录中。

推荐结构如下：

```text
<产物根目录>/
  <方法名>/
    <实验名>/
      seed_<n>/
        config.yaml      # 本次运行的完整配置快照
        train.log        # 训练日志
        metrics.json     # 指标
        checkpoints/     # 权重
```

要求：

- **按方法命名**
  - 用 `vit_encoder/`、`resnet_encoder/` 区分不同方法的结果。
  - 不用 `new/`、`old/`、`v2/` 这类状态词。

- **保存配置快照**
  - 每次运行都保存完整配置。
  - 只看产物目录，也能知道这次运行用了什么设置。

- **不拆散产物**
  - 不把同一次运行的日志、权重、指标分开存放。

## agent 不能做的事

- 不删除任何实验产物，包括 agent 自己刚生成的产物。
- 不移动、不重命名已有产物，包括给旧结果加 `_old` 后缀或移进归档目录。
- 不覆盖已有运行目录；目标目录已存在时先询问用户。

缓存类垃圾（编译缓存、`__pycache__`、`*.pyc`）和 `.agents/tmp/` 里的临时脚本不算实验产物：列出清单，用户确认后由 agent 删除，删完用命令核实。容器留下的 `home/` 目录只删其中的缓存子目录，剩下的内容交给用户，见 records.md。

## 在报告中列出需要用户处理的产物

如果发现以下情况，在最终报告的“需要你处理的实验产物”中列出：

- 旧方法产生的实验产物
- 实验记录中已标为作废的结果
- 散落在统一目录之外的产物
- 本次验证过程中生成的临时产物

每项写清：

- 路径
- 大小
- 属于哪个方法或哪次运行
- 建议处理方式，例如保留、删除、移动到哪里

agent 只提供建议，不执行。
